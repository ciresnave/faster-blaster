    fb_finalize();  // Cleanup

==============================================================================
LAYER 4: WRAPPER FUNCTIONS (blas_lapack_reference_backend.c)
==============================================================================

    fb_blr_saxpy(n, alpha, x, incx, y, incy)  ← CBLAS convention
            ↓
    Lazily load fblas_saxpy_t from DLL
            ↓
    Convert parameters:
        int n          → int n_copy = n; &n_copy
        float alpha    → float alpha_copy = alpha; &alpha_copy
        const float* x → x (pass through)
        int incx       → int incx_copy = incx; &incx_copy
        float* y       → y (pass through)
        int incy       → int incy_copy = incy; &incy_copy
            ↓
    Call: saxpy_(&n_copy, &alpha_copy, x, &incx_copy, y, &incy_copy)  ← Fortran convention


==============================================================================
LAYER 5: DLL LOADING (blas_lapack_reference_backend.c)
==============================================================================

    fb_blr_init()
            ↓
    Search for DLL:
    
    1. Check FB_REFERENCE_BACKEND_PATH environment variable
       Windows: "C:\custom\path\blas_lapack_reference.dll"
       Unix: "/opt/blas_lapack_reference.so"
    
    2. Check same directory as faster-blaster executable
       Windows: "C:\program files\faster-blaster\blas_lapack_reference.dll"
       Unix: "/usr/local/bin/libblas_lapack_reference.so"
    
    3. Check system PATH
       Windows: LoadLibrary("blas_lapack_reference.dll")
       Unix: dlopen("libblas_lapack_reference.so", RTLD_LAZY)
            ↓
    Load DLL:
    
    Windows:  HMODULE g_blr_handle = LoadLibraryA(found_path);
    Unix:     void* g_blr_handle = dlopen(found_path, RTLD_LAZY);
            ↓
    Verify success:
    
    if (g_blr_handle == NULL) {
        FB_ERROR("Could not load reference DLL");
        return false;
    }
            ↓
    Return true, backend marked as available


==============================================================================
LAYER 6: FUNCTION SYMBOL RESOLUTION (blas_lapack_reference_backend.c)
==============================================================================

    User calls: fb_blr_saxpy(100, 2.0f, x, 1, y, 1)
            ↓
    Check if fblas_saxpy_t already loaded:
    
    static fblas_saxpy_t saxpy_fn = NULL;
    if (!saxpy_fn) { ... }
            ↓
    Load symbol from DLL:
    
    Windows: saxpy_fn = (fblas_saxpy_t)GetProcAddress(g_blr_handle, "saxpy_");
    Unix:    saxpy_fn = (fblas_saxpy_t)dlsym(g_blr_handle, "saxpy_");
            ↓
    Verify symbol found:
    
    if (!saxpy_fn) {
        FB_ERROR("Could not load function saxpy_ from reference DLL");
        return;  // Or appropriate error value
    }
            ↓
    Cache function pointer for next calls


==============================================================================
LAYER 7: ACTUAL DLL (blas-lapack-reference project)
==============================================================================

    libf77blas.a (Fortran reference BLAS):
    
    subroutine saxpy(n, alpha, x, incx, y, incy)
        integer n, incx, incy
        real alpha, x(*), y(*)
        do i = 1, n
            y(i) = alpha * x(i) + y(i)
        end do
    end
    
    Compiled by Fortran compiler (gfortran, ifort, etc.):
    - Generates saxpy_() symbol (underscore suffix)
    - All parameters passed by reference (pointers)
    - Called from C via wrapper

        for each backend in [reference, openblas, aocl-blis, ...]:
            for each size in [16, 64, 256, 1024]:
                
                // Generate random test data
                x = random(size)
                y = random(size)

                    operation: "saxpy",
                    backend: backend_name,
                    size: size,

==============================================================================
CONSENSUS VIOLATION DETECTION
==============================================================================

    When all non-reference backends agree but differ from reference:
    
    1. Reference backend computes operation
        → result_ref = 1.234567
    
    2. Backend A computes same operation
        → result_a = 1.234789  (error: 2.2e-4)
    
    3. Backend B computes same operation
        → result_b = 1.234789  (error: 2.2e-4) ← SAME as A!
    
    4. Backend C computes same operation
        → result_c = 1.234789  (error: 2.2e-4) ← SAME as A!
    
    Result: CONSENSUS VIOLATION
    
    → All three non-reference backends agree
    → But they disagree with reference
    → Indicates either:
       a) Reference has a bug
       b) All three backends have the same bug (unlikely)
       c) Numerical tolerance issue (review TOLERANCE_*)
    
    JSON Log:
    {
        "consensus_violation": true,
        "operation": "sgesv",
        "backends_in_agreement": ["aocl-blis", "openblas", "mkl"],
        "reference_result": 1.234567,
        "consensus_result": 1.234789,
        "error": 2.2e-4,
        "size": 256,
        "dtype": "FP32"
    }


==============================================================================
ERROR HANDLING & RECOVERY
==============================================================================

    Scenario 1: DLL Not Found
    
        fb_blr_init()
        └─ Try FB_REFERENCE_BACKEND_PATH → NOT SET
        └─ Try module directory → NOT FOUND
        └─ Try system PATH → NOT FOUND
        └─ Return false, log error
        
        g_blr_initialized = false
        
        Later, user calls fb_call_backend("blas-lapack-reference", ...):
        
        if (!g_blr_initialized) {
            return FB_ERROR_BACKEND_UNAVAILABLE;
        }


    Scenario 2: Function Symbol Not Found
    
        fb_blr_saxpy() called
        └─ Try to load "saxpy_" from DLL
        └─ dlsym() returns NULL
        └─ Log error: "Could not load function saxpy_ from reference DLL"
        └─ Return 0 or void (depends on return type)
        
        Caller gets garbage/zero result, can detect if expected non-zero


    Scenario 3: DLL Exists But is Corrupted
    
        LoadLibrary/dlopen succeeds
        But GetProcAddress/dlsym fails for multiple functions
        
        Mark backend as unavailable if > threshold of functions fail

PERFORMANCE CHARACTERISTICS
==============================================================================

    Operation          Size      Time      Accuracy
    ─────────────────────────────────────────────────
    SAXPY              1e6       2-5 ms    EXACT (floating point)
    DAXPY              1e6       3-8 ms    EXACT (floating point)
    SGEMM              512x512   150 ms    1e-5 relative error
    DGEMM              512x512   300 ms    1e-12 relative error
    SGESV              512x512   400 ms    variable (depends on conditioning)
    DGESV              512x512   900 ms    variable (depends on conditioning)
    
    Reference is NOT optimized:
    - No vectorization (SSE/AVX)
    - No cache blocking
    - No parallelization
    - Single-threaded Fortran
    - Goal: CORRECTNESS, not SPEED
